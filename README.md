## 🎯 为什么传统工具和普通 AI 都在“搞砸”书签？

几乎每个重度网民、开发者和研究者的收藏夹里，都躺着几百个甚至上千个多年未曾打开的陈年链接。在无数次尝试整理的过程中，我们会反复撞上四个极其隐蔽且致命的核心痛点：

### 痛点一：大模型的“好心办坏事”与空间记忆摧毁
很多人的第一反应是：“让 AI 读一遍书签，帮我重新分类整理不就好了？”  
**这恰恰是最大的灾难。**
- 书签是人类大脑的**「空间记忆（Spatial Memory）」**与**「业务上下文」**。比如：你当年为了在境外平台采购技术外链，顺手办了一张虚拟信用卡，所以虚拟卡自然放在垂直业务目录下。
- 大模型只有通用词向量，没有你的私人业务流。一旦让 AI 主观发挥，它会自作聪明地把支付工具生硬塞进一个泛泛的“常用工具”大类里。
- 结果就是：原本按分类整齐存放的东西被翻了个底朝天，你熟悉的抽屉被彻底砸碎，心理感受就是“东西全丢了”。

### 痛点二：传统检测工具对“伪存活与黑产易主”彻底失明
市面上的死链清理扩展（或简单的状态码探测脚本）通常只查 HTTP 状态码是否为 200，导致大量恶劣的“丧尸站点”被误判为健康：
- **域名到期被抢注与灰黑产劫持**：当年收藏的正规技术/电商平台早已停业，域名过期后被黑产批量买走，变成了披着 200 状态码外衣的**涉黄非法站点、境外博彩下注平台、或盗版影视泛站群**；
- **表面 200，实际为伪装 403 / 挂马跳转**：服务器 Nginx 返回 200 OK，但 HTML 标题直接写着 `<title>403 Forbidden</title>`，正文是用 JS 混淆加密的优惠领取或恶意跳转；
- **SSL 证书域名不匹配**：很多老站更换了解析但证书过期或域名不匹配，用户一旦在浏览器点开，直接触发全屏红屏隐私拦截警告（`ERR_CERT_COMMON_NAME_INVALID`）；
- **Cloudflare 致命解析错误**：如被查封的服务，返回 Cloudflare 的 `Error 1000: DNS points to prohibited IP` 错误说明页。  
*如果不做深度证书校验与内容语义比对，这些已经变质的毒性链接会永久潜伏在你的日常收藏夹中。*

### 痛点三：历史归档目录的“灯下黑”与工序污染
很多人习惯建一个名为 `old`、`归档` 或 `历史备份` 的文件夹，本意是把低频、虽然老但可能有用的内容冷冻起来。但在实际治理时，极易产生一种“反正都是老数据，先别去深翻它”的惰性盲区。  
结果导致：死链和黑产站点混在老目录里持续发酵，你打开 `old` 期望看到备查资料，点几个全是报错和违规广告，整个治理流程信任感坍塌。**死链筛查必须具备绝对穿透性，绝不能对历史目录网开一面。**

### 痛点四：Chromium 云同步（Sync）反向覆写的“幽灵回滚”
如果你在后台关闭 Edge/Chrome，直接用脚本修改磁盘上的 `Bookmarks` 文件，重新打开浏览器几秒后，所有被你移走或整理的旧书签又被原封不动拉了回来！  
这是因为现代浏览器开启云同步后，底层同步引擎遵循硬性冲突规则 **「Remote parent wins（云端归属优先）」**。脱机改动没有底层同步事务凭证，联网瞬间会被云端旧版本强制覆盖。

## 🛠️ 我们的解决方案：一套纯 Prompt 驱动的工程质量标准

本项目**不提供任何第三方预编译二进制或代码环境依赖**。我们把在实战中摸索出来的所有踩坑经验与技术死锁，固化为了一套**「通用 Agent 任务配方（PROMPT.md）」**。

你只需要把这份提示词复制丢给你正在使用的本地 AI Agent（如 **Codex、Claude Code、Cursor、Devin** 等），Agent 会现场在你的电脑上自适应理解并严格执行：

```text
┌─────────────────────────────────────────────────────────────┐
│                 书签治理核心闭环（四大准绳）                 │
├──────────────────────────────┬──────────────────────────────┤
│ 1. 结构绝对不动，组内频次浮顶│ 严禁打散已有目录，高频项自然置顶     │
│ 2. 四层穿透探针，清仓隐蔽伪存活│ 结合 SSL 验真与语义对抗，揪出黑产易主│
│ 3. 客观二元隔离，零物理删除  │ 移入隔离箱细分子类，确定死亡项一键清空│
│ 4. 浏览器特权管道，解决云同步│ 注入原生接口更新，微软/谷歌云端永久生效│
└──────────────────────────────┴──────────────────────────────┘
```

1. **绝对零删除 + 空间记忆守恒**：
   原有文件夹（如涉及业务后台、关键工作流的分类）100% 保持不动，书签总数严格守恒。
2. **真假存活与灰产劫持深度识别**：
   直连+本地代理双通道测活（防误杀海外优质站）+ 证书验真 + HTML 标题/正文语义比对，彻底揪出伪装 403、涉黄博彩易主和错误页。
3. **客观状态分流隔离**：
   在书签栏末尾创建 `⚠️ 待核实_疑似失效`，将不可正常浏览的链接细分为：
   - `📁 彻底关停_连接重置`（端口关闭 / RST / Cloudflare Error 1000）
   - `📁 持续超时_无响应`（网络握手无应答）
   - `📁 伪存活_403与404错误页`（状态行 200 但实际为报错或跳转）
   - `📁 业务漂移_黑产篡改与站群`（域名过期被抢注为违规站点或停放出售页）
   - `📁 证书异常_红屏拦截`（证书域名不匹配，浏览器红屏拦截）
   - `📁 空响应与连接中断`（连上后立即断开，0 字节响应）
4. **组内频次浮顶**：
   读取浏览器本地真实历史数据库（`History` SQLite），在各个原有文件夹内部把高频访问项自动置顶，低频项自然沉底。
5. **宿主原生特权注入**：
   指导 Agent 通过系统管道向正在运行的书签管理页（`edge://favorites` 或 `chrome://bookmarks`）注入原生脚本，直接调用内部特权接口 `chrome.bookmarks.move()`，使变动实时提交给云同步服务器，彻底解决回滚问题。

## 🚀 极速使用指引

1. 打开本项目中的 [PROMPT.md](PROMPT.md)；
2. 复制全部内容；
3. 打开你本地的 AI Agent（Codex / Claude Code / Cursor 等），粘贴并发送；
4. Agent 会现场与你确认浏览器类型、代理端口及白名单保护目录，确认后在 1 分钟内自动完成全套治理，无需手动安装任何插件。
